# Directrices del Asistente para GDinamy

## Idioma de Comunicación
- **Responder siempre en español**: Todas las interacciones, explicaciones, preguntas, resúmenes y propuestas deben realizarse en español.
- **Convención de código y comentarios**: Mantener el español para el código de dominio, comentarios y documentación técnica (`respaldo`, `restauracion`, `base_datos`, etc.), en consistencia con el diseño del proyecto.

## Referencia de Arquitectura y Normas
- Consultar [CLAUDE.md](CLAUDE.md) para detalles específicos de arquitectura (Tauri v2 + Vue 3 + Pinia + sidecars de MongoDB), comandos de desarrollo y reglas de linting.

## Flujo de Trabajo y Convenciones de Git
- **Commits**: Seguir estrictamente la convención de [Conventional Commits](https://www.conventionalcommits.org/) (ej. `feat:`, `fix:`, `docs:`, `refactor:`, `chore:`).
- **Ramas**: Utilizar el modelo de ramas **Git Flow** (`main`/`develop`, ramas `feature/*`, `release/*`, `hotfix/*`).
- **Seguimiento y Documentación**: Las tareas y documentación se coordinan mediante **GitHub Issues** y el tablero del proyecto **"GDinamy - Backups MongoDB"** en GitHub.
